# Community

Z3r0 welcomes users, security researchers, and software engineers building reliable, operator-guided multi-agent workflows for authorized security assessment, penetration testing, vulnerability discovery, and responsible technical research.

## Scope

Community discussion and contributions focus on the project and its technical domains, including:

1. Multi-agent runtime design, context management, and task continuity.
2. Security assessment and penetration testing workflows, vulnerability discovery, code auditing, and evidence modeling.
3. Sandbox isolation, distributed execution resources, controlled egress, and operational security.
4. LightRAG document ingestion, retrieval quality, graph data, and model integration.
5. Frontend usability, API contracts, documentation, testing, and deployment reliability.

## Participation

Keep technical discussions specific, evidence-based, and respectful. Do not publish credentials, private target data, or material outside the active project scope; prefer synthetic examples and isolated test assets for demonstrations.

Z3r0 assumes that user-provided objectives, targets, and examples are lawfully authorized. It grants no additional access rights; keep contributions within the active project scope and applicable law.

**Contributors remain responsible for their conduct and compliance. The author and maintainers accept no responsibility for damage, loss, claims, or liability arising from user contributions or use.**

## Safe Demonstrations and Contributions

Examples, issue reports, and pull requests should preserve the project's non-destructive operating model. Use local fixtures, synthetic or canary data, mock services, or captured samples, and keep demonstrations to the smallest reproducible proof. Do not include instructions or automation for persistence, unauthorized privilege acquisition, lateral movement, data exfiltration, destructive writes, service exhaustion, or bypassing scope and safety controls. Redact sensitive material and report it privately when public disclosure could increase risk.

Changes that add network or sandbox behavior should document scope gates, rate and resource limits, stop conditions, rollback or cleanup, and evidence handling. Maintainers may request a safer test harness or decline changes that cannot be demonstrated without material impact.

## Contributing

Use GitHub issues for reproducible bug reports and scoped feature proposals. Pull requests should keep changes focused, explain user-visible behavior, include proportionate verification, and update documentation when contracts or workflows change.
